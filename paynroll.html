EUC PayNRoll

Designing and developing a centralized web application that simplifies enrollment, student records, and transaction management for the university's Registrar's Office.

Role
UI/UX Designer & Developer
Team
Individual Project
Platform
Responsive Web Application
Tools
Figma · HTML · CSS · JavaScript
01

The problem

Enrollment and academic transaction processes can become difficult to manage when information is spread across different steps, records, and administrative tasks. The Registrar's Office needed a more centralized digital experience for managing student information, enrollment activities, and related transactions.

The challenge was to create a web application that could organize these processes without making the experience feel overwhelming. Students and administrative users needed clear access to the information and actions relevant to their respective workflows.

02

Who it's for

Primary

The registrar / administrator

  • Needs centralized access to student academic records
  • Manages enrollment and transaction-related information
  • Needs an organized interface for completing administrative tasks
Secondary

The student

  • Needs a clear way to understand enrollment-related information
  • Wants easier access to academic and transaction records
  • Needs confidence that submitted information is properly recorded
03

04

Research & insights

Research focused on understanding enrollment workflows, registrar requirements, student record management, and how information architecture could reduce friction across administrative processes.

Finding
Enrollment and student administration involve multiple pieces of information that need to be accessed and updated throughout the process.
Implication
Users need a clear overview of important records, statuses, and actions without having to navigate through unnecessary screens.
Action
Organized the experience around centralized information, task-oriented navigation, and clearly grouped administrative functions.
Finding
Administrative interfaces can become difficult to scan when student records and transaction information are presented without a strong visual hierarchy.
Implication
Frequently accessed information and primary actions should be visually prioritized.
Action
Used structured layouts, grouped content, and consistent interface patterns to make important information easier to scan.
05

Structure & flow

The application was structured around the core administrative workflows of the Registrar's Office. Instead of treating every feature as an isolated screen, the experience connects related information and actions into a more predictable workflow.

Login / Access
→
Dashboard / Overview
→
Student Records
→
Transactions / Actions

The information architecture was designed around the user's primary tasks. Each area of the system supports a specific administrative need while maintaining a consistent navigation structure across the application.

06

Design exploration

The visual direction explored how to present an administrative platform with a large amount of information without making the interface feel unnecessarily complex. The final direction prioritized hierarchy, readability, and clear access to important actions.

Option A — Rejected

A dense dashboard that exposed too much information at once. Although functional, the layout made it difficult to determine which information and actions should receive immediate attention.

Option B — Selected

A structured administrative interface that prioritizes essential information, separates major tasks, and uses consistent visual patterns throughout the application.

07

Key design decisions

Tasks before complexity
The interface prioritizes the actions administrative users need to complete instead of presenting every available function at the same visual level.
Hierarchy, not information overload
Student records, transaction information, and important system states are grouped and prioritized so users can quickly identify what matters.
Consistency across workflows
Consistent layouts, spacing, navigation patterns, and interface components help users build familiarity as they move between different areas of the application.

Outcome

EUC PayNRoll evolved from a UX/UI concept into a functional web application, demonstrating the ability to translate user flows, information architecture, and interface decisions into an implemented digital product.

The project demonstrates end-to-end product thinking across interface design and implementation, including responsive layouts, structured navigation, administrative workflows, and functional web development.

11

Reflection

What I learned

Designing and implementing EUC PayNRoll reinforced how important information architecture becomes when working with complex systems. Good UI is not only about how individual screens look, but also about how users move between tasks and understand the information presented to them.

What I'd improve

Given more time, I would conduct usability testing with administrative and student users to identify workflow friction, validate navigation patterns, and better understand which information users need most frequently.

What I'd do next

I would next refine the administrative dashboard, expand interaction states, improve responsive behavior across breakpoints, and continue validating the end-to-end enrollment and transaction workflows with real users.
